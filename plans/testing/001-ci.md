## Target result

One documented local command and one checked-in GitHub Actions workflow run the
repository's maintained verification gates, including performance, protocol and Swift coverage.
Browser E2E is currently unmounted and `test:e2e` is absent from `package.json`.
[Web 025](../canopy-web/025-arbor-web.md) (formerly Web 023) owns its restoration;
add the browser CI job when that gate returns. This does not block initial CI.

The current manual gate is:

```sh
bun install
bun run typecheck
bun run test
bun run test:protocol
bun run build
bun run test:performance
swift test --package-path canopy-swift/Packages/ArborSyncClient
```

`bun run test:protocol` exercises portable fixtures plus disposable live Overstory
Sync and canopyd checks against Swift clients, so at least one job needs a macOS
Swift toolchain. Postgres integration remains opt-in when its DSN is absent.

## Scope

In scope:

- a canonical `verify` script composed from existing scripts;
- `.github/workflows/verify.yml` for pushes and pull requests;
- pinned Bun/action versions and frozen dependency installation;
- Playwright browser installation/cache once Web 025 restores the maintained browser gate;
- repository-wide Markdown relative-link and local-anchor validation, including
  durable docs, active plans, historical records, and examples;
- separate fast, browser, protocol/Swift, and performance jobs when that makes
  failures clearer;
- README documentation that points to the canonical command and explains any
  platform-specific jobs.

Out of scope:

- changing product code or weakening a gate to make CI pass;
- fixing unrelated flakes inside the workflow change;
- adding a formatter, linter, release process, deployment, or Postgres service;
- hiding failures with broad retries or `continue-on-error`.

## Steps

1. Run every documented gate locally and record environmental versus product
   failures before adding CI.
2. Add a `verify` script that composes the platform-neutral maintained gates
   without duplicating their command bodies.
3. Add a Linux fast/performance job where supported and a macOS
   protocol/Swift job for the cross-language harness. Keep job boundaries
   explicit if the complete suite would otherwise hide the failing layer.
4. Use `bun install --frozen-lockfile` and preserve the repository's skipped-without-DSN
   Postgres behavior. Add the required Playwright browser only with the restored browser job.
5. Add one deterministic Markdown-link checker that understands Overstory's
   extensionless document links and sibling-body directory semantics. Run it
   against durable docs, plans, `_done`, fixture notes, and examples.
6. Update `DEVELOPMENT.md` so local and CI entry points cannot drift.
7. Review the workflow permissions and keep them read-only unless a concrete
   checked-in step requires more.

## Done criteria

- [ ] One local command runs the maintained platform-neutral gates.
- [ ] Pushes and pull requests run typecheck, Bun tests, build, performance,
  protocol conformance, and standalone Swift coverage. Browser coverage has an explicit
  Web 025 dependency and joins CI when its maintained gate returns.
- [ ] Workflow permissions and action/runtime versions are explicit.
- [ ] Relative Markdown links and local anchors are validated without requiring
      generated or ignored output.
- [ ] No required failure is skipped, ignored, or converted to a warning.
- [ ] `DEVELOPMENT.md` and the workflow invoke the same underlying package scripts.

## STOP conditions

- A baseline product gate is red before CI changes.
- A required gate needs credentials or production data not already supplied by
  a safe repository mechanism.
- GitHub-hosted runners cannot provide the required macOS/iOS toolchain without
  a larger CI design decision.
- The only apparent route to green is deleting, skipping, or broadly retrying a
  failing test.
