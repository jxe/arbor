# The command line
*Part of the [Overstory spec](README.md), layer 2 (clients): the `story` command as scripts, agents and runners call it. Its conventions, the commands for folders, agents, identity and sync state, their arguments, exit codes and JSON output. How a command-line client talks to its own sync service, how it installs itself, and what it prints for people are reference choices ([CLI reference](../getting-started/cli.md)).*

A command-line client conforms when every command below accepts the arguments shown,
means what this chapter says, exits as §1.3 says, and with `--json` prints the shapes
given here. Human-readable output is not part of the contract: scripts read `--json`, exit
codes and the files a command writes. A JSON object may carry fields not listed here, which
a reader ignores.

## 1. Conventions

### 1.1 Operands

- A **local path** may be relative on input; output and persisted placements use
  canonical absolute paths.
- A **tree location** is an HTTPS URL or an `overstory://` locator
  ([locators §1](1.6-locators.md#1-forms)). Where a command takes a *locator*, it also
  takes a local path.
- `--dry-run` may synchronize as needed to check that the command can run, but never
  applies the move or changes placement or canonical configuration.
- A **duration** is a number with a unit: `30s`, `5m`, `1h`.

### 1.2 The sync service and the environment

Commands that act on placed folders talk to a sync service (Story Sync, in the reference
implementation), selected in this order:

1. `STORY_SYNC_URL`, when set;
2. the agent session ([§3.2](#32-sessions-start-finish-and-run)) whose root contains the
   command's local path;
3. the person's persistent service.

A command never starts a private service of its own to run itself: when none answers, it
fails and says how to start one. Reads that need only durable configuration (`story me`,
the account list in `story sync status`) work without a service.

| Variable | Means |
|---|---|
| `STORY_SYNC_URL` | the sync service to use |
| `STORY_HOME` | the data home, for a service run outside the default one |
| `STORY_CLOUD_BUNDLE` | an agent bundle ([§3.1](#31-bundles)), instead of an argument |
| `STORY_RUN_REQUEST` | a run request, instead of `--task` |
| `STORY_AGENT_SESSION` | the agent session that `story agent` reports land in |
| `STORY_AGENT_LABEL` | the agent's name in presence |

Giving a value both as an argument and in the environment is a usage error.

### 1.3 Exit codes

| Code | Means |
|---|---|
| `0` | success |
| `1` | an operational failure; the message on standard error says what |
| `2` | malformed usage, after printing the command's synopsis |
| `75` | `story agent run` only: the command succeeded but its last changes could not be sent; finish with `story agent finish` |

`story agent run` otherwise exits with its command's status, or 128 plus the signal number
when a signal ended it. Everything a command says for people goes to standard error when its
standard output is a value a script reads (a bundle, JSON).

### 1.4 JSON output

Every `--json` object has `schemaVersion: 1`. A reader rejects a version it doesn't know.

## 2. Folders

### 2.1 `story place`

```text
story place [--clear-access] [--access <subject>=<read|write|none>[,...]] <local-path> <canonical-url>
story place <canonical-url> <local-path>
story place --read-only <canonical-url> <local-path>
```

- **Local first** declares the tree at the URL, creating it with a new `TreeID` if it is
  vacant, and places it at the folder. With no access options a new tree is private.
  `--access` takes subjects as access rules name them (`public`, `~handle`, a profile
  locator; [access control §1](3.2-access-control.md)), may repeat, and `none` removes a
  rule; `--clear-access` removes every rule first. The URL selects the claimed account
  whose address contains it, the most specific when addresses nest; two equally specific
  matches fail. Creating a tree needs a device that administers that account.
- **Canonical first** places an existing tree of a claimed account at the folder. It takes
  no access options.
- On another host, both forms use the person's placement account there
  ([federation §2](3.3-federation.md#2-placement-accounts)), connecting this device to it
  on first use, and fail with what to ask that host's administrators when no placement root
  is reserved.
- **`--read-only`** follows a tree at any host: with an account there, as a visitor
  ([federation §5](3.3-federation.md#5-visitor-sessions)), or as anyone, and never sends
  edits made in the folder.

### 2.2 `story mv`

```text
story mv [--dry-run] <placed-local-root> <new-local-path>
story mv [--dry-run] <source-canonical-url> <destination-canonical-url>
```

- **Two local paths** move one placement's folder on the same filesystem. The tree must be
  present, writable, clean and idle; the destination must not exist or overlap another
  placement. The `TreeID`, host, canonical URL, access, contents and history don't change.
  A failure rolls back where it can.
- **Two canonical URLs** on one account rename the tree at its host, leaving its folder,
  `TreeID`, contents, access and history unchanged. The tree must be placed here and idle,
  the device must administer the destination account, and the destination must be vacant.
  URLs on two hosts are refused: a tree stays on the host that holds it.
- A local and a canonical operand together are a usage error.

### 2.3 `story open`

```text
story open [<locator>]
```

Opens the locator, by default the current directory, in a browser client of the person's
sync service. It fails when no service answers.

## 3. Agents and runners

### 3.1 Bundles

```text
story agent create [--name <label>] --place <canonical-url> <relative-path> [...]
story agent list [--json]
story agent revoke <bundle-id>
```

An **agent bundle** is a revocable credential that lets an agent on another machine work in
chosen folders. `create`, on a device that administers the account, makes a new
non-administrator device of the account and prints its credential, and nothing else, to
standard output: an agent link ([locators §2.3](1.6-locators.md#23-agent-links)) when the
bundle places one tree under its own name, otherwise one opaque bundle string. Every
`--place` names a writable tree root of one account on one host and a relative path under
the agent's root; the paths are disjoint and stay inside the root. The printed value is
secret, reusable and at most 32 KiB.

`list --json` prints `{ schemaVersion: 1, bundles }`, where each bundle is `{ bundleID,
label, createdAt, origin, account, configurationTree, deviceID, trees }` and `trees` lists
TreeIDs; it never holds a credential or a path. `revoke` removes the bundle's device, which
ends its watches and requests; it can't retract what an agent already downloaded.

### 3.2 Sessions: start, finish and run

```text
story agent start [<bundle>] [--task <run request>] [--root <directory>] [--timeout <duration>] [--json]
story agent finish [--root <directory>] [--timeout <duration>] [--json]
story agent run [<bundle>] [--root <directory>] [--timeout <duration>] [-- <command> [<argument>...]]
```

A bundle is the argument or `STORY_CLOUD_BUNDLE`. `--root` defaults to the current directory
and `--timeout` to five minutes.

- **`start`** checks the bundle's trees out under the root, starts a sync service for them
  that outlives the command, and exits `0` once every tree is present, writable, idle and
  equal to its accepted root at the host. It prints instructions for an agent working
  there: where each tree is, to edit files in place keeping each page's `id:` and links,
  how to report with `status` and `done`, and to run `finish` when done. A new root must be
  absent or empty. A failed start may be retried.

  `--json` prints `{ schemaVersion: 1, ready: true, sessionID, bundleID, root, origin,
  label, placements, instructions }`, where each placement is `{ treeID, canonicalURL,
  relativePath, path }` and `label` is the agent's name in presence (the bundle's label).

  **`--task`** takes a run request ([reading and watching §3.6](1.2-reading-and-watching.md#36-runners-and-messages))
  as JSON, or `@` and a file holding it, or `STORY_RUN_REQUEST`. With a bundle the task runs
  in the new checkout; without one, in the tree as placed on this machine. Presence shows
  the agent under the request's `run` from then on, and its `done` ends the run and marks
  the task. `--json` adds `run: { id, tree, page, task, state, result, prompt? }`, where
  `state` is `queued`, `running`, `finished`, `failed`, `stopped` or `undone`, and `prompt`
  is the task as the agent should be told it. Sending the same `run` twice runs it once.
- **`finish`** syncs one last time, proves every folder equals its accepted root, stops the
  session's service and removes its private state. `--json` prints `{ schemaVersion: 1,
  finished: true, sessionID, root, placements }`. When it can't prove that before its
  timeout it exits `1` and keeps the session for another `finish`.
- **`run`** is `start`, the command with the root as its working directory, then `finish`,
  whatever way the command ends. The command inherits standard input, output and error,
  without `STORY_CLOUD_BUNDLE`; `run` itself writes only to standard error. SIGINT and
  SIGTERM pass to the command and the final send still happens. With no command it starts
  `$SHELL` when standard input is a terminal, else it is a usage error. It exits as §1.3
  says. `--timeout` bounds the checkout and the final send separately.

### 3.3 Reporting

```text
story agent status <text> [--at <text on the page>]
story agent done <text>
```

From an agent in a placed folder: `status` says what it is doing, and `--at` points its
cursor at the first occurrence of that text on its page; `done` says what it did and ends
its presence a few seconds later (and its run, in a run session). Both land in
`STORY_AGENT_SESSION`'s session when it is set, and do nothing outside a placed folder. A
client shows them in presence ([reading and watching §3](1.2-reading-and-watching.md#3-presence)).

## 4. Identity

```text
story me
story me create [<profile-folder>] [--name <display-name>]
story me set [--name <display-name>] [--avatar <relative-path>] [--description <text>]
story me domain [<domain>] [--remove <domain>] [--check]
story me accounts
story me device [--account <ConfigurationTreeID>]
```

- **`me create`** makes the person's one profile identity
  ([accounts and devices](3.1-accounts-and-devices.md)): a new Ed25519 key kept in the
  operating system's credential store, its Profile TreeID, and a `type: person` root in the
  profile folder (by default `~/.story/profile`), which must be empty or already this
  profile. It contacts no host and never replaces another identity.
- **`me`** prints the Profile TreeID, the profile folder and whether the private key is
  here. It changes nothing.
- **`me set`** changes the profile root's presentation frontmatter, keeping its body and
  other keys. An avatar is a PNG, JPEG, GIF or WebP file inside the profile folder.
- **`me domain <domain>`** adds the domain to the profile's `domains` and prints the two
  records, either of which completes the claim ([locators §1.1](1.6-locators.md#11-domain-locators));
  `--remove` takes one out; `--check` resolves every listed domain as a host would and
  exits `1` when one doesn't name this profile.
- **`me accounts`** lists the home account and placement accounts, each with the folders
  placed on it. **`me device`** prints this installation's device and key for an account;
  `--account` is needed only when several are connected.

## 5. Sync state

```text
story sync status [<locator>] [--json]
story sync pause <placed-path>
story sync resume <placed-path>
story sync pending <placed-path> [--json]
story sync declined <placed-path> [--json]
story sync declined restore <placed-path>
story sync declined resend <placed-path>
```

`story status` is short for `story sync status`.

- **`status`** reports the sync service, connected accounts and placed trees, or, with a
  locator, its enclosing tree. It never starts a service, syncs, or changes anything, and
  exits `0` whenever it can report, even when the service is stopped. `--json` prints
  `{ schemaVersion: 1, ready, context, runtime, cloudSession?, live?, selection?,
  diagnostics }`:
  - `ready` is true when the service runs, any agent session is ready, and every tree in
    scope is `up-to-date`. Scripts wait on it.
  - `runtime.state` says whether the service is running.
  - `live.trees.snapshot` lists trees, each with `id` and `condition`: one of
    `up-to-date`, `syncing`, `paused`, `offline`, `declined`, `conflict`, `error`,
    `missing` or `not-placed`.
  - `cloudSession`, when the path is in an agent session, is `{ id, root, phase, targets }`.
  - `diagnostics` is a list of `{ code, message }`.
- **`pause`** stops publishing the placed folder holding the path, across restarts, until
  **`resume`**; updates from elsewhere still arrive, and `status` says `paused`.
  **`pending`** shows what would be sent next; `--json` prints the exact update request
  ([updates and merging §1](1.3-updates-and-merging.md#1-the-update-request)). Resuming sends what the last
  `pending` showed.
- **`declined`** lists the paths a host declined
  ([working trees §6](2.1-working-trees.md#6-accepted-conflicts-and-held-local-work)), where their content
  is now, and the host's reason. **`restore`** puts back the host's version of those paths
  and keeps other changes; **`resend`** sends them again as they are.

## 6. Not specified

How a command-line client installs or supervises its sync service (`story daemon`),
installs agent hooks into a particular agent (`story agent install`, `hook`, `uninstall`),
backs up a key (`story me backup`, `restore`), invites people (`story invite`), and what
any command prints for people are reference choices, described in the
[CLI reference](../getting-started/cli.md).
