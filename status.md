# Arbor implementation status

Local Arbor Sync is internally decomposed into sync, account and browser handlers,
a filesystem object source and a narrow connection provider. Its process,
loopback API and disk formats remain unchanged; no file mirror was introduced.
`Workspace` now separates its folder lifecycle from an explicit editor/provider
component while retaining recovery at open. Sync conflicts use the existing
identity-checked review path; the unused coarse resolver is removed.
See [ownership](docs/reference-implementation.md#local-service-ownership).

This page reports what the reference implementation does today. The [specification](spec.md) is intentionally broader: it defines the portable system Arbor is building toward. Active work belongs in [plans](plans/README.md), and completed evidence belongs in [plans/_done](plans/_done/README.md).

## Implemented and tested

- **Native working-tree editors.** The Mac app and iOS edit placed Arbor trees directly as working trees (`ArborWorkingTree` over `ArborObjectStore`): Markdown remains canonical, the document admission machine makes each edit durable in the working tree, and the update coordinator publishes durable heads to Canopy. The daemon has no editor path; it is the folder's client plus loopback bootstrap, credential, and object services.
- **Native editor recovery.** Native saves now wait for durable coordinator heads; committed editor generations also retain independent exact-source local recovery copies and admission diagnostics. Mac reconnection retries native pending work. Restart recovery, divergent-draft review, local History restore, disk-failure retry and uncommitted-keystroke races have focused regressions. The changes are source-built and not yet installed or manually verified; see [native editor recovery](docs/native-editor-recovery.md).
- **Tree identity and synchronization.** Stable TreeIDs, immutable objects, content-addressed retained-root snapshot bundles, accepted updates, append-only update strings, three-way text merging, watch streams, sparse object transfer, canonical boundaries, and public HTML/Markdown projection are implemented in TypeScript and Swift with shared fixtures.
- **Exact-basis admission preparation.** TS/Swift admission effects capture original source/revision; Native validates and delivers source intents and retains guarded patches in backward-readable editor recovery. The target contract no longer requires local compare-and-swap review for a stale Canopy basis. Runtime stale admission and removal of legacy conflict UI still await complete client integration and broader deployed Canopy acceptance; see [008](plans/reliability/008-enable-source-operations.md#next-milestone-durable-stale-basis-admission-and-complete-client-acceptance).
- **TS source admission consumer.** Document sessions retain accepted/authored revision identity and admit captured source offline. The publisher retains exact requests across failures, installs Canopy projections and settles conflict-bearing acceptance without a local review hold. Disposable-server coverage includes stale admission, restart, hidden successors and equal-root resolution. These remain library APIs; installed Native emission remains pending. See the [queue checkpoint](docs/source-admission-queue.md).
- **Native mixed admission queue.** Source-enabled Swift providers durably retain structural snapshots, imports and assets alongside source operations and expose pending creations/moves to reads. Private Trash survives snapshot reconstruction and restart. Disposable Canopy verifies mixed publication after uncertain acceptance; branched local work preserves navigation and document intent while temporarily gating further structural actions. The app switch stays off pending deployment verification and release checks. See the [queue checkpoint](docs/source-admission-queue.md).
- **Durable source admission queue.** Swift and TS now retain exact source/basis/candidate records with explicit accepted or authored predecessors, validation on recovery and deterministic operation-bearing request preparation. Native captures the graph and accepted identity atomically before a watch can advance it. Swift now has opt-in session read-your-writes, publication, receipt settlement and draft recovery, with failure/restart tests. Real disposable Canopy scenarios now verify root and nested stale range admission after several peer updates, restart, hidden-candidate continuation and second-client resolution. TS integration, structural writes and broader editor/server release gates remain; installed-client operation emission is still disabled. See the [queue checkpoint](docs/source-admission-queue.md).
- **Client state machines.** The document admission machine (native editor; one transport, no digest fence) and the working-tree update machine (native working trees, the daemon's folder synchronizer) are pure reducers in both languages that execute one shared fixture (`document-admission`, `working-tree-updates`; no filesystem role). A burst of edits is one admission and normally one accepted update; at most one request is in flight per document session and per tree, with one retained successor. Both language implementations are verified by the unit and protocol suites, the Swift package suites on macOS, and an app smoke test on macOS and the iOS simulator.
- **Canopy communities and accounts.** A Canopy can host a community plus person and group profile trees, reserve account paths, enforce whole-tree access, and reconcile synchronized account configuration.
- **Profile identity and claiming.** `arbor me create` creates a self-certifying person Profile TreeID. A community reserves that exact identity and the client proves control through the signed challenge/claim flow.
- **Plural local accounts and devices.** One Arbor data home can hold several Canopy accounts, including multiple accounts at one origin. Account configuration uses `account.yaml`, `trees.yaml`, and `devices.yaml`; native account pairing has passed its recorded Mac-to-iPhone primary-path acceptance.
- **Short-lived cloud workspaces.** The CLI can mint a reusable one-account cloud bundle, materialize its exact writable tree placements under an isolated root, keep them synchronized through a detached Arbor Sync, verify and stop through an explicit finish boundary, revoke the bundle device, and report persistent, foreground, or cloud state through `arbor status`.
- **Headless executable-data core.** The checked-in Supplies corpus has SQLite-backed query lowering and execution, dependency-sensitive live result streams, and authorized transactional mutations with durable retry receipts.

## Partial or in progress

- **Consolidated Wire target on main.** The portable specification and paired TS/Swift target models define material references, atomic resolution declarations, ordinary reconciliation with optional exact-state guards, simplified acceptance outcomes, predecessor identity chains and paged inspection without fixed decision-count caps. The specification requires retained rule evidence with open per-rule schemas, without a dedicated evidence endpoint. Shared vectors test grammar and identity; semantic scenarios remain implementation targets. Active request/read adoption is described below. Installed builds are unchanged. The source-edit engine and superseded bounded-inspection implementation remain on `codex/source-intent-experiment`. Follow the [contract and adoption boundary](docs/update-wire-contract.md) and [Plan 011](plans/reliability/011-compatible-accepted-ambiguity.md).

- **Wire format stabilization.** Raw file objects, explicit file/directory/tree entries, sparse bootstrap without a file map, and optional accepted-conflict metadata are implemented in TypeScript and Swift. Migration 005 has rewritten the live trees and reset history after synchronized-client checks and two production-copy rehearsals. Mac and iPhone are upgraded; only the soak remains. Conflict review UI remains deferred; deployed Canopy now accepts the whole-entry alternatives described below.
- **Composable conflict backend experiment.** An isolated [Jujutsu-style term backend](docs/conflict-terms-experiment.md) accepts ordinary Wire projections with retained alternatives in a separate SQLite database. It exercises continued editing, partial text resolution, exact bytes, request replay, stale-review fencing, process-death recovery, and scoped retention. It reproduced and now rejects an ordinary edit whose algebraic cancellation would silently clear a conflict. The experiment is not mounted or exported by Canopy; page moves, production merge policies, and extension/client integration remain open.
- **Protocol-ready source intent.** The ordinary Wire update model now requires authored change IDs, explicit snapshot/operation semantics, resolution declarations and optional exact-state guards in TypeScript and Swift, with cross-language grammar and digest fixtures. Snapshot clients emit `operations: null` and `resolves: []`; durable requests preserve identities, operations, and prefix ordering. Deployed Canopy supports the exact-basis subset described below, with whole-batch rejection of unsupported forms. Accepted commits guard update identity as well as root. Semantic execution, editor operation capture, advanced provenance merges, and the upgraded conflict UI remain planned in [008](plans/reliability/008-enable-source-operations.md), [009](plans/reliability/009-canopy-provenance-merges.md), and [010](plans/reliability/010-client-conflict-review.md). The server upgrade is deployed; installed clients remain snapshot-only. See the historical [coordinated upgrade procedure](docs/protocol-ready.md).
- **Conflict intent model.** A separate [source-intent model](docs/conflict-intent-comparison.md) extends the experiment with paragraph targets, authored revision identity, move/copy effects, causal deletion and selective undo, and explicit alternative edits. Its 20 tests include a paired snapshot/intent test for editing an alternative back to old base bytes without clearing the conflict and reconstructing semantic requests after serialization. Source correspondence is an input, not inferred; range lineage, real editor integration, bounded history, and production persistence remain unimplemented.

- **Working-tree client transition ([Native 022](plans/native/022-run-the-mac-app-as-a-working-tree-client.md)).** Plan A (Phases 0 through 7) is implemented; the live Mac switch, the iPhone re-place, and the soak remain. Arbor Sync serves `GET /v1/bootstrap` as an accepted-root sparse installation boundary plus placement/routing metadata, `GET /v1/credential`, and `GET /v1/objects/{hash}` backed by a stat-tuple-keyed object index with periodic revalidation and Canopy fetch-through; Canopy's object route serves any retained accepted root. Bootstrap deliberately excludes the daemon's mutable folder head, pending request, conflict, availability, and tree-list sync status. Both native platforms run the Swift working-tree client (`ArborWorkingTree` over `ArborObjectStore`): the Mac opens the accepted bootstrap as an independent in-memory working tree, uses the daemon only for object bytes and the shared credential, and publishes its own durable heads directly to Canopy regardless of the folder client's state; visits are app-side read-only working trees following the tree's watch. The Swift core no longer exposes cross-client request adoption or dirty-folder pending seeding. iOS re-places on working-tree format `5`. The daemon's editor path is deleted: no node, mutation, admission, asset, import, or session routes, no editor admission or search index, no `ArborSyncWorkspaceProvider`; the fixture has no filesystem role and one admission transport. The CLI's one tree write (`arbor place`) edits the configuration checkout on disk. The web editor is unavailable until Plan B rebuilds it as the same independent accepted-root client; `packages/render` stays in the repository, unmounted. The live Mac switch and the iPhone re-place wait for Joe's go-ahead (synchronize the phone first), then a soak of a couple of weeks before Plan B.
- **Native publication progress fix (on main, not installed).** Two reproduced coordinator stalls are corrected: a no-work pass left preparation active, and preparation errors bypassed recovery/status handling. Both regressions and the 60-test working-tree suite pass; live validation remains. See the [investigation](docs/native-sync-progress.md).
- **Exact source execution foundation.** A pure `editSource` executor validates basis/object/range references, exact lineage and complete candidate reconstruction. It retains equal-byte edit evidence. Exact-basis acceptance now persists tree-scoped provenance atomically, including equal-byte edits. Disjoint concurrent plain-text/prose edits from one retained accepted basis now merge with durable rule/contribution evidence. Overlaps, snapshot barriers and changed causal bases still conflict; whole-entry accepted ambiguity is implemented as described below. Schema 11 and this server acceptance slice are deployed; installed clients still emit snapshots. See the [checkpoint](docs/exact-source-execution.md).
- **Accepted whole-entry conflicts (server deployed).** Root and nested source edits, including partial ranges across longer source/snapshot histories, retain per-file alternatives and acknowledge normally. Snapshot saves, deletion, stale edits and batch suffixes preserve attribution; authorized historical inspection and guarded partial resolution are implemented. Schema 11 retains nested decision locations and typed hidden-object dependencies atomically; an offline migration from 8/9/10 preserves history. The filesystem and Swift Wire clients are exercised against real accepted conflicts. The [code-only follow-up](docs/ancestor-conflicts-deployment.md) also deployed coupled ancestor changes and guarded snapshot resolution without a schema upgrade. Source-built Canopy also accepts source successors of merged predecessors using retained prefix correspondence. Fine-grained range decisions, automatic range translation across merged predecessors, direct alternative edits and review UI remain. See the [checkpoint](docs/accepted-entry-conflicts.md).
- **Source-region representation foundation.** A pure same-basis partition/projection module preserves independent overlapping regions, exact text and operation identities, with explicit choices and no byte-equality resolution. Its unit corpus covers bridging overlaps, insertion anchors and byte fidelity. Acceptance and persistence still use whole-entry alternatives; durable range decisions and their continuation/inspection/resolution lifecycle remain to be integrated.
- **Durable fragment graph proof (isolated).** A separate SQLite experiment validates two independent source choices, hidden/length-changing edits, ancestor deletion and opaque replacement without enumerating combinations. Restart, guarded partial resolution, historical reads, exact retry and transaction rollback are exercised. This is representation evidence, not production range acceptance; schema 11, clients and deployment are unchanged. See the [storage proof](docs/conflict-fragment-storage.md).
- **Client conflict transition is the priority.** Fine-grained storage adoption is deferred to [Canopy storage 002](plans/canopy-storage/002-composable-conflict-fragments.md). Swift/TS admission reducers enforce retained-basis sessions without local CAS review; Native no longer applies the legacy equal-byte success shortcut in that mode. Real Quagmire-to-Canopy protocol scenarios cover stale admission, editor-only draft recovery, client restart, accepted conflict, continued editing and server-owned resolution. Source emission remains opt-in; structural/TS consumer integration, legacy-work transition and release gates remain before retiring the old Native conflict machinery.
- **Schema 8 → 11 rehearsal passed.** A fresh Railway backup preserved all 493 accepted updates/observations and 1,090 objects through migration, idempotent rerun and local startup with full integrity checks. Active Mac/iPhone coordinator records contained no retained conflicts, holds or pending requests. The subsequent [live cutover](migrations/009-nested-conflict-locations/live-cutover.md) deployed schema 11 and passed full integrity, snapshot write, exact retry and cleanup checks. Arbor Sync caught up with all three placements idle. Installed clients and source emission are unchanged; the user confirmed both apps load normally after reopening and phone refresh. See also the historical [rehearsal evidence](migrations/009-nested-conflict-locations/rehearsal.md).
- **Accepted-state contract deployed.** Canopy and both client languages use simplified receipts, predecessor identity/root chains and required unresolved signals. Schema 8 retains predecessor IDs and flags; an offline migration preserves history/digests and refuses incomplete legacy chains. Filesystem/native replay separates accepted identity from observation progress and preserves pending work at equal roots. The September 15 joint cutover preserved all 276 accepted records; signed Mac/iPhone clients, exact-replay and cross-device restart checks pass. Ordinary-use/offline observation and investigation of a pre-cutover Native sync stall remain. See the [checkpoint](docs/update-wire-contract.md#active-accepted-state-adoption).

- **Consolidated request adoption.** Active TS/Swift request codecs, snapshot constructors, durable request encoding and Canopy validation use the consolidated contract. Canopy enforces `ifCurrent` against accepted identity after replay lookup. Tests cover same-root advancement, sparse transfer, exact retries, and recovery without rewriting incompatible old queues. Accepted-state/watch adoption and remaining cutover gates are recorded in [Plan 011](plans/reliability/011-compatible-accepted-ambiguity.md). This implementation has not been deployed.

- **Native conflict review.** Direct replicas and the macOS Arbor Sync status panel materialize verified base/current/mine/server-draft content and offer per-path Current/Mine/Both/Edit choices through the shared review surface. Arbor Sync retains fetched evidence across restart, identity-fences submissions, refuses to fabricate choices when a conflict has no durable Canopy evidence, pauses approximate accepted Markdown merges before materializing them, and repeats an accepted moving-filesystem prefix by request digest instead of reapplying it against a stale base. Ordered replay of an unattempted update suffix and Quagmire's future inline hunk accessories remain in [Reliability 004](plans/reliability/004-contextual-canopy-conflict-resolution.md).
- **Executable documents.** The data/query/mutation core exists, but MDX/TSX compilation, generated typing, editor integration, React presentation, automatic activation, native presentation, and Canopy hosting are not complete. [Apps 001 and 003](plans/README.md#product-completion) own that work.
- **Client parity.** Arbor web and native Arbor share the core model and synchronization contracts, but their interaction surfaces are not identical.
- **Group management.** Arbor web can add and remove structured members on an existing `type: group` tree. It does not provide one coherent Create Group flow, and native Arbor has no equivalent membership editor. This remains a separately tracked product-design item.
- **Operational hosting.** Railway/VPS deployment, persistent storage, backup/restore, and coordinated alpha upgrades are documented, but production recovery, dispute handling, and high availability are not productized.

## Specified but not implemented

- Canopy-hosted Arbor agents and their portable frontmatter contract.
- Static baking and additional portable live-deployment adapters.
- A complete Postgres child provider, observation contract, and bidirectional projections.
- Several deferred workspace capabilities, including multiple local placements of one TreeID, durable pinned historical placements, and reader-local overlays.

## Compatibility and known gaps

- The current v2 account-configuration layout is live, while the named v1 account and local-state readers remain during an explicit compatibility window. [Cleanup 002](plans/cleanups/002-retire-v1-account-and-local-state-adapters.md) owns their eventual removal.
- Scalar group-member entries are legacy input compatibility only. Conforming authored content uses a required `profile` locator and optional Canopy-local `handle` as defined by [accounts and devices](spec/04-accounts-and-devices.md).
- Linux and Windows daemon supervision adapters are not implemented.
- Canopy exposes no accepted-history listing or metadata. Known retained roots are readable through immutable snapshots by callers who can currently read the tree; the generic object route remains current-root-scoped.
- There is no polished first-party group creation flow; users should not be directed to a manual YAML recipe as if one existed.
