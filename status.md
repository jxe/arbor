# Arbor implementation status

Local Arbor Sync is internally decomposed into sync, account and browser handlers,
a filesystem object source and a narrow connection provider. Its process,
loopback API and disk formats remain unchanged; no file mirror was introduced.
`Workspace` now separates its folder lifecycle from an explicit editor/provider
component while retaining recovery at open. Sync conflicts use the existing
identity-checked review path; the unused coarse resolver is removed.
See [ownership](docs/reference-implementation.md#local-service-ownership).

This page reports what the reference implementation does today. The [specification](spec.md) is intentionally broader: it defines the portable system Arbor is building toward. Active work belongs in [plans](plans/README.md), and completed evidence belongs in [plans/_done](plans/_done/README.md).

- **Merge authority integration (deployed 2026-09-17).** Canopy forwards all eight specified operations to the merge process and atomically owns accepted/authored semantic states, inspection identities and complete immutable dependencies in additive schema 12. Existing source editors and snapshot clients keep their Wire contract. Whole-file choices remain the initial presentation policy; structural ambiguity uses enclosing decisions. See the [integration checkpoint](docs/merge-authority-integration.md) and [migration rehearsal](migrations/010-merge-state/README.md).

- **Operation capture and source review (implemented, not installed).** Canopy now defaults to independent source-range choices, with exact fragment reads, guarded resolution and placement ranges bound to accepted bytes. Whole-file policy remains available and format rules can couple choices. Swift/TS retain verified source lineage and equal-byte intent; Native emits ordinary and compound sibling-body entry moves/copies, including post-copy page-ID edits, and explicit removals for private Trash. Restore retains snapshot creation semantics and survives restart. Explicit same-document copies of source-backed blocks now survive editor recovery and publish as `copySource`; Source editor undo/redo now preserves transaction targets through debounce and recovery and publishes named inverses; live tests preserve independent peer edits. Same-tree cross-document copies, page-conversion undo/redo and durable undo-horizon collection are also implemented locally. Transformed copies and other existing compound editor commands remain in Native 008. The editor-accessory API is released and pinned at Quagmire 0.8.0; app installation and hands-on verification remain separate. See the [capture checkpoint](docs/source-admission-queue.md#supported-operation-capture-checkpoint--september-17).

## Implemented and tested

- **Native working-tree editors.** The Mac app and iOS edit placed Arbor trees directly as working trees (`ArborWorkingTree` over `ArborObjectStore`): Markdown remains canonical, the document admission machine makes each edit durable in the working tree, and the update coordinator publishes durable heads to Canopy. The daemon has no editor path; it is the folder's client plus loopback bootstrap, credential, and object services.
- **Native editor recovery.** Native saves now wait for durable coordinator heads; committed editor generations also retain independent exact-source local recovery copies and admission diagnostics. Mac reconnection retries native pending work. Restart recovery, divergent-draft review, local History restore, disk-failure retry and uncommitted-keystroke races have focused regressions. These changes are installed; cross-device source publication and restart were manually verified, while injected-failure scenarios remain automated coverage; see [native editor recovery](docs/native-editor-recovery.md).
- **Tree identity and synchronization.** Stable TreeIDs, immutable objects, content-addressed retained-root snapshot bundles, accepted updates, append-only update strings, three-way text merging, watch streams, sparse object transfer, canonical boundaries, and public HTML/Markdown projection are implemented in TypeScript and Swift with shared fixtures.
- **Exact-basis admission preparation.** TS/Swift admission effects capture original source/revision; Native validates and delivers source intents and retains guarded patches in backward-readable editor recovery. The target contract no longer requires local compare-and-swap review for a stale Canopy basis. Installed Native uses retained-basis admission; stale admission, restart and continued editing have live-server coverage; see [008](plans/native/008-complete-native-move-copy-undo-capture.md).
- **TS source admission consumer.** Document sessions retain accepted/authored revision identity and admit captured source offline. The publisher retains exact requests across failures, installs Canopy projections and settles conflict-bearing acceptance without a local review hold. Disposable-server coverage includes stale admission, restart, hidden successors and equal-root resolution. These remain library APIs; installed Native emission is described below. See the [queue checkpoint](docs/source-admission-queue.md).
- **Native mixed admission queue.** Source-enabled Swift providers durably retain structural snapshots, imports and assets alongside source operations and expose pending creations/moves to reads. Private Trash survives snapshot reconstruction and restart. Disposable Canopy verifies mixed publication after uncertain acceptance; branched local work preserves navigation and document intent while temporarily gating further structural actions. Installed Mac and iPhone builds now use source admission; the [live cutover](docs/native-source-cutover.md) verified source publication, cross-device propagation and restart. The source now removes the unused rejected-update workspace, hold/resolution machine and review UI; this cleanup is built and tested but not yet installed. Unexpected old conflict/hold records fail without rewriting saved work. See the [queue checkpoint](docs/source-admission-queue.md).
- **Durable source admission queue.** Swift and TS now retain exact source/basis/candidate records with explicit accepted or authored predecessors, validation on recovery and deterministic operation-bearing request preparation. Native captures the graph and accepted identity atomically before a watch can advance it. Swift now has opt-in session read-your-writes, publication, receipt settlement and draft recovery, with failure/restart tests. Real disposable Canopy scenarios now verify root and nested stale range admission after several peer updates, restart, hidden-candidate continuation and second-client resolution. TS editor-host integration and richer operations remain; installed Native now emits the supported source operations and explicit structural snapshots. See the [queue checkpoint](docs/source-admission-queue.md).
- **Client state machines.** The document admission machine (native editor; one transport, no digest fence) and the working-tree update machine (native working trees, the daemon's folder synchronizer) are pure reducers in both languages that execute one shared fixture (`document-admission`, `working-tree-updates`; no filesystem role). A burst of edits is one admission and normally one accepted update; at most one request is in flight per document session and per tree, with one retained successor. Both language implementations are verified by the unit and protocol suites, the Swift package suites on macOS, and an app smoke test on macOS and the iOS simulator.
- **Canopy communities and accounts.** A Canopy can host a community plus person and group profile trees, reserve account paths, enforce whole-tree access, and reconcile synchronized account configuration.
- **Profile identity and claiming.** `arbor me create` creates a self-certifying person Profile TreeID. A community reserves that exact identity and the client proves control through the signed challenge/claim flow.
- **Plural local accounts and devices.** One Arbor data home can hold several Canopy accounts, including multiple accounts at one origin. Account configuration uses `account.yaml`, `trees.yaml`, and `devices.yaml`; native account pairing has passed its recorded Mac-to-iPhone primary-path acceptance.
- **Short-lived cloud workspaces.** The CLI can mint a reusable one-account cloud bundle, materialize its exact writable tree placements under an isolated root, keep them synchronized through a detached Arbor Sync, verify and stop through an explicit finish boundary, revoke the bundle device, and report persistent, foreground, or cloud state through `arbor status`.
- **Headless executable-data core.** The checked-in Supplies corpus has SQLite-backed query lowering and execution, dependency-sensitive live result streams, and authorized transactional mutations with durable retry receipts.

## Partial or in progress

- **Resource policy and execution authority (deployed 2026-09-18).** Apps 004 has shared TS/Swift rule grammar, governed resource-policy indexing, host-private execution tokens, guarded scoped snapshot effects, revocation streams and Migration 011 preparation. Restrictive conflict acceptance, exact administrator resolution and Native consent/edit preservation are implemented. Scope limitations and remaining rehearsal/migration gates are recorded in the [implementation checkpoint](docs/resource-policy-implementation.md). - **Consolidated Wire target on main.** The portable specification and paired TS/Swift target models define material references, atomic resolution declarations, ordinary reconciliation with optional exact-state guards, simplified acceptance outcomes, predecessor identity chains and paged inspection without fixed decision-count caps. The specification requires retained rule evidence with open per-rule schemas, without a dedicated evidence endpoint. Shared vectors test grammar and identity; semantic scenarios remain implementation targets. Active request/read adoption and installed-client status are described below. The source-edit engine and superseded bounded-inspection implementation remain on `codex/source-intent-experiment`. Follow the [contract and adoption boundary](docs/update-wire-contract.md) and [Plan 011](plans/verification/011-client-compatibility.md).


- **Wire format stabilization.** Raw file objects, explicit file/directory/tree entries, sparse bootstrap without a file map, and optional accepted-conflict metadata are implemented in TypeScript and Swift. Migration 005 has rewritten the live trees and reset history after synchronized-client checks and two production-copy rehearsals. Mac and iPhone are upgraded; only the soak remains. Conflict review UI remains deferred; deployed Canopy now accepts the whole-entry alternatives described below.
- **Composable conflict backend experiment.** An isolated [Jujutsu-style term backend](docs/conflict-terms-experiment.md) accepts ordinary Wire projections with retained alternatives in a separate SQLite database. It exercises continued editing, partial text resolution, exact bytes, request replay, stale-review fencing, process-death recovery, and scoped retention. It reproduced and now rejects an ordinary edit whose algebraic cancellation would silently clear a conflict. The experiment is not mounted or exported by Canopy; page moves, production merge policies, and extension/client integration remain open.
- **Accepted-prefix performance (deployed 2026-09-18).** Source-batch preflight reuses exact accepted authored states instead of executing an accepted prefix again. Native omits object payloads for durably acknowledged prefix edits without changing request identities. A production-copy request with five accepted updates plus one new update fell from 15.58 to 6.15 seconds with identical accepted output; repeated history verification remains a cost. See the [measurement and validation boundary](docs/canopy-update-performance.md).
- **Incremental merge-state work (worktree only).** Indexed history maps support incremental execution for ordinary exact-basis source replacements; shared historical piece pages, incremental graph/material validation, compact acceptance roots, preflight reuse, and one persistent FIFO worker reduce repeated work. Per-update tree storage quotas are removed; periodic accounting is deferred. Other operations and divergent merges use the full evaluator. Canopy reuses typed history validation proofs while checking current material and dependency availability; shared-first worker reads, disposable atomic staging, and reuse of the host-validated basis bring a small local warm fast-forward sample to 74–76 ms (28–29 ms in the worker). Divergent-merge latency is not yet established, and cold history verification is slower. Wire is unchanged and nothing from this worktree is deployed. See the [remaining work and measurements](docs/canopy-update-performance.md#incremental-state-worktree-not-deployed).
- **Protocol-ready source intent.** The ordinary Wire update model now requires authored change IDs, explicit snapshot/operation semantics, resolution declarations and optional exact-state guards in TypeScript and Swift, with cross-language grammar and digest fixtures. Snapshot clients emit `operations: null` and `resolves: []`; durable requests preserve identities, operations, and prefix ordering. Deployed Canopy supports the exact-basis subset described below, with whole-batch rejection of unsupported forms. Accepted commits guard update identity as well as root. Additional operations, advanced provenance merges, and the upgraded conflict UI remain planned in [008](plans/native/008-complete-native-move-copy-undo-capture.md), [009](plans/canopy/009-canopy-provenance-merges.md), and [010](plans/native/010-client-conflict-review.md). The server upgrade is deployed; installed Native now emits supported source operations, while filesystem clients retain snapshot submission. See the historical [coordinated upgrade procedure](docs/protocol-ready.md).
- **Conflict intent model.** A separate [source-intent model](docs/conflict-intent-comparison.md) extends the experiment with paragraph targets, authored revision identity, move/copy effects, causal deletion and selective undo, and explicit alternative edits. Its 20 tests include a paired snapshot/intent test for editing an alternative back to old base bytes without clearing the conflict and reconstructing semantic requests after serialization. Source correspondence is an input, not inferred; range lineage, real editor integration, bounded history, and production persistence remain unimplemented.

- **Working-tree client transition ([Native 022](plans/_done/native/022-run-the-mac-app-as-a-working-tree-client.md)).** Plan A (Phases 0 through 7) is implemented and live on Mac and iPhone; the explicit soak closeout remains in [release verification](plans/verification/release-and-soak.md#observation-and-soak-closeout). Arbor Sync serves `GET /v1/bootstrap` as an accepted-root sparse installation boundary plus placement/routing metadata, `GET /v1/credential`, and `GET /v1/objects/{hash}` backed by a stat-tuple-keyed object index with periodic revalidation and Canopy fetch-through; Canopy's object route serves any retained accepted root. Bootstrap deliberately excludes the daemon's mutable folder head, pending request, conflict, availability, and tree-list sync status. Both native platforms run the Swift working-tree client (`ArborWorkingTree` over `ArborObjectStore`): the Mac opens the accepted bootstrap as an independent in-memory working tree, uses the daemon only for object bytes and the shared credential, and publishes its own durable heads directly to Canopy regardless of the folder client's state; visits are app-side read-only working trees following the tree's watch. The Swift core no longer exposes cross-client request adoption or dirty-folder pending seeding. iOS re-places on working-tree format `5`. The daemon's editor path is deleted: no node, mutation, admission, asset, import, or session routes, no editor admission or search index, no `ArborSyncWorkspaceProvider`; the fixture has no filesystem role and one admission transport. The CLI's one tree write (`arbor place`) edits the configuration checkout on disk. The web editor is unavailable until Plan B rebuilds it as the same independent accepted-root client; `packages/render` stays in the repository, unmounted. The later [source cutover](docs/native-source-cutover.md) records installed clients, exact cross-device publication and restart evidence; do not repeat the old switch or re-place steps.

## Compatibility and known gaps

- The current v2 account-configuration layout is live, while the named v1 account and local-state readers remain during an explicit compatibility window. [Cleanup 002](plans/cleanups/002-retire-v1-account-and-local-state-adapters.md) owns their eventual removal.
- Scalar group-member entries are legacy input compatibility only. Conforming authored content uses a required `profile` locator and optional Canopy-local `handle` as defined by [accounts and devices](spec/04-accounts-and-devices.md).
- Linux and Windows daemon supervision adapters are not implemented.
- Canopy exposes no accepted-history listing or metadata. Known retained roots are readable through immutable snapshots by callers who can currently read the tree; the tree-scoped object route also serves objects reachable from retained accepted roots, subject to current read access.
- There is no polished first-party group creation flow; users should not be directed to a manual YAML recipe as if one existed.
